# 図面比較・左右表示モード設計

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-09-04 |
| 対象 | Vite版 PDF差分レビューア |
| 関連仕様 | `local/図面差分ビューア_仕様書.md` §5.2〜5.5 |
| 実装範囲 | 図面比較の左右表示、同期ビュー操作、PNG/PDF出力 |

## 1. 目的

図面比較では、差分オーバーレイと新旧切替に加えて、旧版と新版を同時に見比べたい場面がある。
テキスト比較と同様に旧版を左、新版を右へ並べ、同じ図面位置を同期して確認できる「左右表示」を第3の表示モードとして追加する。

## 2. 決定事項

- 図面比較の「差分」「新旧切替」に「左右表示」を追加する。既存2モードは残す。
- 左ペインに旧版、右ペインに位置合わせ済みの新版を表示する。
- 変更枠は左右表示中、旧版・新版の両方へ常に表示する。
- ズーム、パン、全体表示、1:1、ページ送りは左右で同期する。
- 左右表示中は変更枠の追加・削除・移動・リサイズを行わない。差分モードで編集した枠は左右表示へ反映する。
- PNGとPDFは旧版と新版を横並びで合成し、両側へ変更枠を焼き込む。
- PDFや差分結果を外部へ送信しない。

## 3. 検討した方式

### 採用: 図面比較専用の2ペイン表示

既存の図面レンダリングと位置合わせ処理を再利用し、図面比較内に専用の2ペイン表示と同期ビューポートを追加する。
差分・新旧切替の単一Canvas経路を維持でき、今回の変更による回帰範囲を限定できる。

### 不採用: 1枚のCanvasへ左右を常時合成

保存処理は単純になるが、画面幅への追従、ペイン単位のラベル、フィット計算が不自然になる。
大判・高DPIでは表示用Canvasの面積が倍になり、モード切替時のメモリ負荷も大きい。

### 不採用: テキスト比較と図面比較を汎用2ペインビューアへ全面統合

長期的な共通化余地はあるが、テキストのページ単位座標と図面の位置合わせ済み共通フレームでは描画責務が異なる。
今回の要望に対して改修範囲と回帰リスクが過大なため行わない。

## 4. UIとモード遷移

図面比較の表示モードボタンを次の3つにする。

1. 差分
2. 新旧切替
3. 左右表示

左右表示を選ぶと単一Canvas領域を隠し、次の2ペイン領域を表示する。

```text
+--------------------------+--------------------------+
| OLD                      | NEW                      |
| 旧版ページ + 変更枠       | 位置合わせ済み新版 + 変更枠 |
+--------------------------+--------------------------+
```

共通の図面比較ツールバーは維持する。
左右表示中は新旧切替インジケータを隠し、「変更点を強調」はON表示のまま操作不可、「枠を編集」および編集時専用ボタンは無効化する。
モードを離れる際に `boxEditor.showBoxes` の利用者設定は変更せず、左右表示だけが変更枠を常時描画する。

モード切替後も現在ページ、DPI、しきい値、位置ズレ許容、手動・自動位置合わせ、ズーム／パン状態を維持する。
左右表示へ初めて入ったとき、または「差分を表示」直後は全体フィットする。

## 5. 描画アーキテクチャ

### 5.1 状態

`state.visual.mode` に `"split"` を追加する。
左右表示のページキャッシュと共有ビュー状態を `state.visual` 配下へ保持する。
描画世代と文書世代は既存の図面比較と共用し、古い非同期描画のコミットを防ぐ。

### 5.2 ページ準備

既存の `prepareVisualPage` を使用し、次を得る。

- 旧版のページCanvas
- 向き・用紙寸法・回転・拡縮・移動を反映した新版Canvas
- 両版共通の作業フレーム寸法
- 位置合わせ結果とキャッシュ

旧版側は共通フレーム寸法の白Canvasへ旧版ページを描く。
新版側は既存の `alignedNewCanvas` を用いる。
これにより左右Canvasは同じ幅・高さ・画像座標を持ち、同一のCSS transformで同じ図面位置を表示できる。

### 5.3 変更枠

手編集済み枠があるページはその枠を使用する。
ないページは既存の位置合わせ済み差分計算から自動枠を1回だけ取得する。
左右それぞれの表示用Canvasへ同じ枠を描くが、キャッシュされた元ページCanvasには描き込まない。

左右表示では `boxEditor.showBoxes` に関係なく枠を描く。
モードを離れると、差分／新旧切替では従来どおり `boxEditor.showBoxes` に従う。

### 5.4 欠落ページ

片側に対応ページがない場合も共通フレーム寸法の白Canvasを生成し、中央へ「この版にこのページはありません」と表示する。
存在する側の変更枠は両ペインへ同一座標で表示し、ページ追加・削除の対応位置を確認できるようにする。

## 6. 同期ビューポート

左右表示専用のビューポート制御を追加し、`{ scale, tx, ty }` を両Canvasへ同時適用する。

- 片側でのホイール操作を、操作したペイン内のポインタ位置を中心とする同期ズームとして扱う。
- 片側でのドラッグを両Canvasの同期パンとして扱う。
- 「全体」は共通フレーム全体を各ペインへ収める。
- 「1:1」は画面1pxとCanvas 1pxを一致させる。
- ページ送り後は倍率と位置を維持する。

差分／新旧切替では既存の単一Canvasビューポートを使用する。
ツールバーとイベントハンドラは現在の `visual.mode` に応じて操作先を切り替える。

## 7. 出力

### 7.1 PNG

左右表示中のPNGは、フル解像度の旧版と新版を横並びに合成する。
上部にOLD／NEWとページ番号を描き、両側へ変更枠を焼き込む。
ファイル名は `side-by-side_p{ページ番号}.png` とする。

### 7.2 PDF

左右表示中のPDFは全ページをPNGと同じ横並び構成で生成し、`side-by-side.pdf` として保存する。
各ページの用紙寸法は合成Canvasの縦横比に合わせる。
差分／新旧切替での既存出力挙動は変更しない。

表示用CSS transformは出力へ使用せず、常にフル解像度のCanvasを合成する。

## 8. エラー処理と競合制御

- ページ移動やモード切替で新しい描画が始まった場合、古い描画結果をコミットしない。
- Worker処理は既存の対話描画レーンと出力レーンを使用し、画面描画とPDF生成が互いをキャンセルしないようにする。
- 文書の再読み込みで進行中の描画・出力を無効化する。
- CanvasまたはBlob生成に失敗した場合は既存のエラー表示経路へ渡し、操作ボタンを処理前の状態へ戻す。

## 9. テスト方針

### 単体・統合

- `visual.mode` が `diff`、`toggle`、`split` を保持できる。
- 左右ページが同じ共通フレーム寸法で生成される。
- 位置合わせ済み新版と旧版へ同じ変更枠が描かれる。
- 手編集枠が自動枠より優先される。
- 同期ズーム、パン、全体、1:1の計算が両Canvasへ同一適用される。
- 連続するページ移動・モード切替で古い描画結果が破棄される。
- PNG/PDF用の横並び合成にOLD／NEW、ページ番号、両側の変更枠が含まれる。

### E2E

- 第3ボタンで左右表示へ切り替え、旧版と新版が左右へ表示される。
- 片側のズーム／パンが両側へ同期する。
- ページ送り、回転、拡縮、移動、自動位置合わせを反映する。
- 片側欠落ページを所定メッセージで表示する。
- 左右表示から差分／新旧切替へ戻っても既存機能が動作する。
- 左右表示のPNGおよび全ページPDFを保存できる。

## 10. 受け入れ基準

1. 図面比較に「左右表示」が第3モードとして表示される。
2. 左に旧版、右に位置合わせ済み新版が表示され、両方に変更枠が常時表示される。
3. ズーム、パン、全体、1:1、ページ送りが左右同期する。
4. 差分モードで手編集した枠が左右表示とその出力へ反映される。
5. 左右表示中は枠編集ができず、差分モードへ戻ると従来どおり編集できる。
6. PNGは現在ページ、PDFは全ページを旧版｜新版の横並びで保存する。
7. 片側にページがない場合も処理が失敗せず、欠落側を明示する。
8. 既存の差分、新旧切替、テキスト比較、従来の出力に回帰がない。
9. `npm test`、`npm run build`、対象E2Eが成功する。
10. 処理はブラウザ内で完結し、PDFを外部送信しない。
