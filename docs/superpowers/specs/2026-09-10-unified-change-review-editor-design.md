# 変更箇所一覧と枠編集の統合設計

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-09-10 |
| 対象 | Vite版 PDF差分レビューア |
| 先行仕様 | `docs/superpowers/specs/2026-09-07-change-review-list-design.md` |
| 実装範囲 | 変更箇所一覧、枠編集、Undo、サイドバー開閉、全体ミニマップ |

## 1. 目的

変更箇所の確認と枠の手編集を右サイドバーへ集約する。

利用者が一覧上の対象を明示してから編集する構成へ変え、全体編集モードとレビュー操作の行き来をなくす。

サムネイルから変更箇所へ拡大した後もページ内の位置を把握できるように、図面ビューへ全体ミニマップを追加する。

## 2. 適用範囲

| 対象 | 扱い |
|---|---|
| 図面比較の差分モード | 対象 |
| 図面比較の新旧切替モード | 対象 |
| テキスト比較モード | 対象外 |
| 変更枠の作成、移動、リサイズ、削除 | 対象 |
| 確認状態とコメント | 対象 |
| 変更枠操作のUndo | 対象 |
| 確認状態とコメントのUndo | 対象外 |
| レビューセッションのファイル保存 | 対象外 |
| PNGおよびPDFへのコメント出力 | 対象外 |

PDF、変更枠、レビュー情報はブラウザのメモリ内だけで扱う。

外部API、テレメトリ、クラウドストレージは使用しない。

## 3. 先行仕様との関係

この設計は先行仕様の変更箇所一覧を拡張する。

内容が競合する場合は、次の項目に限ってこの設計を優先する。

- レビュー状態は「未確認」と「確認済み」の2値とする。
- 「対象外」は廃止し、不要な変更箇所は削除する。
- 一覧項目の「編集」から対象枠の編集を開始する。
- ツールバーの「変更箇所一覧」と「枠を編集」は廃止する。
- 変更箇所サイドバーは境界上の開閉ボタンで操作する。
- 拡大中の図面ビューへ全体ミニマップを表示する。
- 「自動検出に戻す」はUndo可能なページ操作とする。

全ページ索引、変更種別、レビュー情報の引継ぎ、サムネイル生成、Workerレーン、出力処理は先行仕様を維持する。

## 4. 採用する操作モデル

変更箇所一覧を、レビューと枠編集をまとめた**変更箇所インスペクター**として扱う。

枠編集の状態は次の三つとする。

- **通常**：一覧選択、前後移動、拡大表示、確認、コメントを受け付ける。
- **選択枠編集**：選択した一つの枠だけを移動またはリサイズできる。
- **新規作成**：図面上のドラッグで新しい変更枠を一つ作る。

選択枠編集では枠内のドラッグで位置を移動し、四隅と四辺の計八つのハンドルで大きさを変更する。

新規作成が完了したら、その枠を選択した選択枠編集へ移る。

別の一覧項目で「編集」を押した場合は、確定済みの変更を保持したまま編集対象を切り替える。

## 5. 状態モデル

変更枠の幾何情報を正本とし、レビュー情報は安定した変更IDをキーにして分離して保持する。

一覧は現在有効な変更枠から作る投影であり、一覧だけに存在する変更項目は作らない。

選択中の変更IDはレビュー状態側で一つだけ保持する。

枠配列内の位置は描画またはポインター操作時にIDから求め、永続的な選択識別子には使わない。

枠編集状態の概念形は次のとおりとする。

```js
{
  mode: "idle" | "edit" | "create",
  drag: null | {
    pointerId,
    kind: "move" | "resize" | "create",
    handle,
    originalRect,
    previewRect
  },
  editsByPage: Map,
  undoByPage: Map
}
```

枠編集は操作開始時にレビュー状態の選択IDを受け取り、対象枠の配列位置をその都度求める。

レビュー情報は次の形とする。

```js
{
  changeId: {
    status: "pending" | "confirmed",
    comment: ""
  }
}
```

削除した枠のレビュー情報は、Undoで同じIDを復元できる間は内部に残す。

比較条件の変更またはPDFの差し替えによって履歴から到達不能になったレビュー情報は、既存の整理処理で破棄する。

## 6. 変更箇所サイドバー

サイドバーは図面ビューの右側へ配置し、デスクトップ幅では320pxを基準幅とする。

差分を初めて表示したときに開く既存の動作を維持する。

ツールバーの「変更箇所一覧」とサイドバー見出しの閉じるボタンは廃止する。

代わりに、図面ビューとサイドバーの境界上へ常設の開閉ボタンを置く。

- 閉じているときは `«` を表示し、押すとサイドバーが左方向へ開く。
- 開いているときは `»` を表示し、押すとサイドバーが右方向へ閉じる。
- 支援技術向けの名前は「変更箇所を開く」と「変更箇所を閉じる」に切り替える。

サイドバー上部には次を固定表示する。

```text
変更箇所 17件
確認済み 6 / 17    未確認 11件

[前の変更] [次の変更]
[＋ 新規変更箇所]
[このページを自動検出に戻す]
```

「このページを自動検出に戻す」は、そのページに手編集がある場合だけ有効にする。

テキスト比較モードではサイドバーと開閉ボタンを表示しないが、開閉状態は保持する。

サイドバーを閉じる場合とテキスト比較モードへ移る場合は通常状態へ戻し、選択IDと確定済みの枠変更は保持する。

## 7. 一覧項目

各一覧項目には次を表示する。

- 変更番号
- ページ番号
- 種類（追加、削除、変更）
- 「確認済み」チェックボックス
- 「編集」ボタン
- 「削除」ボタン
- 変更箇所のサムネイル
- コメント入力欄

チェックが外れている項目を未確認、チェックされている項目を確認済みとして集計する。

削除した項目は一覧から外し、進捗の分母にも含めない。

追加または削除の後はページ番号と座標による表示順から変更番号を振り直し、変更番号を内部IDとして使わない。

項目の見出しまたはサムネイルを押すと、その変更箇所を選択して図面上で拡大表示する。

チェックボックス、編集、削除、コメントの操作では、意図しない拡大表示を起こさない。

編集対象の項目には琥珀色の左線と「編集中」を表示し、「編集」ボタンの表示を「編集を終了」へ変える。

確認状態はチェックだけに依存せず、「確認済み」というラベルでも判別できるようにする。

## 8. 枠の編集

一覧項目の「編集」を押すと、次の順に操作する。

1. 対象ページを表示する。
2. 対象枠を選択する。
3. 対象枠が収まる倍率と位置へ移動する。
4. 変更枠の表示を有効にする。
5. 選択枠編集へ切り替えて八つのハンドルを表示する。

選択枠編集では空白部分のドラッグによる新規作成を受け付けない。

枠を移動またはリサイズするときは、ページ外へ出ないように座標を制限する。

ポインターを離した時点で変更を確定し、座標が変わった場合だけUndo履歴へ追加する。

右クリックと別ポインターからのイベントは編集操作として扱わない。

`Esc`または「編集を終了」で通常状態へ戻る。

## 9. 新規変更箇所

「＋ 新規変更箇所」を押すと新規作成へ切り替え、図面上のカーソルを十字形にする。

利用者が図面上をドラッグすると作成予定枠を表示する。

ポインターを離した時点で有効な大きさなら、次の初期値で変更項目を作る。

- 種類：`changed`
- 状態：`pending`
- コメント：空文字列
- 出所：`manual`

作成した項目には新しい変更IDを発行し、一覧へ追加して選択枠編集へ移る。

逆方向のドラッグは正規化し、ページ外の座標はページ境界へ収める。

画面上の最小寸法を満たさない場合は作成せず、「枠が小さすぎます」と通知する。

`Esc`を押した場合は枠を作らず通常状態へ戻る。

## 10. 削除と自動検出への復帰

一覧項目の「削除」を押すと、確認ダイアログを出さずに対象枠を削除する。

削除後は「変更箇所を削除しました。Ctrl+Zで元に戻せます」と通知する。

削除した枠が選択中または編集中だった場合は、選択と編集状態を解除する。

選択枠編集では`Delete`キーでも同じ削除操作を実行できる。

「このページを自動検出に戻す」は、ページ内の複数の手編集を置き換えるため実行前に確認する。

実行時は現在の手編集枠をUndo履歴へ保存してから、自動検出枠へ戻す。

復帰後にCtrl+Zを押すと、直前の手編集枠とレビュー情報を復元する。

## 11. Undo

Undo履歴はページごとに保持する既存方式を継続する。

Ctrl+Zは現在ページで最後に確定した次の操作を戻す。

- 新規作成
- 移動
- リサイズ
- 削除
- 自動検出への復帰

確認チェックとコメントは枠のUndo履歴に含めない。

テキスト入力欄、テキストエリア、編集可能要素にフォーカスがある場合は、Ctrl+Zをブラウザの文字編集へ渡す。

履歴は既存上限の新しい50件を保持する。

Undoで枠が復元された場合は、同じ変更IDに紐づく確認状態とコメントを再表示する。

## 12. 全体ミニマップ

図面ビューが全体表示より拡大されている間、ビュー内へ**全体ミニマップ**を表示する。

サムネイル選択による拡大と手動ズームを同じ条件で扱い、表示倍率が全体表示倍率を1%以上超えた場合に表示する。

ミニマップには次を描く。

- 現在の差分Canvasを縮小したページ全体
- 現在見えている範囲を示す琥珀色の矩形
- 選択中の変更枠を示す追加、削除、変更の種別色の線

ミニマップをクリックすると、その位置が図面ビューの中央に来るようにパンする。

表示範囲の矩形をドラッグすると、図面ビューを連続してパンする。

移動先はページの表示可能範囲へ制限する。

ミニマップ上の操作は枠編集のポインター操作へ伝播させない。

ページ画像は表示済みCanvasから縮小生成して再利用する。

ズームとパンではページ画像を再生成せず、表示範囲の矩形だけを更新する。

ミニマップと選択表示はPNGおよびPDFへ出力しない。

## 13. レイアウトと外観

既存の製図用UIの配色、書体、線による情報階層を維持する。

使用する基本色は次のとおりとする。

- 作業面：`#0e151d`
- パネル：`#151f2a`
- 操作面：`#1b2836`
- 境界線：`#2a3947`
- 文字：`#e8eef4`
- 選択と操作：`#f4b942`

追加、削除、変更の種別色は既存の青、赤、琥珀色を維持する。

通常UIには既存のサンセリフ書体を使い、座標、ページ、進捗には既存の等幅書体を使う。

項目ごとの装飾的な影や浮遊カードは追加せず、境界線と左線でページ、項目、選択状態を区別する。

ミニマップは図面の内容を隠しすぎない寸法とし、デスクトップ幅ではビュー右下へ置く。

画面幅が狭い場合はサイドバーを右側のドロワーとして重ね、ミニマップをビュー左下へ移してドロワーとの重なりを避ける。

ドロワー外側の押下と、編集状態ではないときの`Esc`でサイドバーを閉じられるようにする。

デスクトップ幅でサイドバーを開閉した場合は、全体表示中なら新しい表示領域へ再度合わせる。

拡大中なら表示していたページ座標の中心を維持し、ミニマップの表示範囲を更新する。

## 14. アクセシビリティ

開閉、編集、削除、新規作成はキーボードで操作できるネイティブボタンとして実装する。

確認状態にはラベル付きのネイティブチェックボックスを使う。

すべての操作部品へ視認できるフォーカス表示を設け、色だけで状態を伝えない。

変更通知には`aria-live="polite"`を使う。

`Esc`の処理順は次のとおりとする。

1. 新規作成中なら作成を中止する。
2. 選択枠編集中なら編集を終了する。
3. 狭幅のサイドバーが開いているなら閉じる。

## 15. エラー処理と競合制御

- PDF未読込または差分未生成の場合は、新規作成と編集操作を無効にする。
- 古い文書世代、描画世代、索引世代の結果は既存どおり状態へ反映しない。
- 編集開始のためのページ移動中に別項目が選ばれた場合は、最後の選択だけを反映する。
- ページ移動、サイドバー収納、モード変更では未確定のドラッグを破棄し、確定済みの編集は保持する。
- サムネイル生成の失敗は編集、確認、コメントを妨げない。
- ミニマップ用画像を生成できない場合はミニマップを隠し、図面のズームとパンを継続できるようにする。
- 比較条件の変更またはPDF差し替えでは、既存の手編集破棄確認を維持する。

## 16. モジュール境界

既存モジュールの責務を保ち、画面イベントを一つのコントローラへ集中させない。

- `src/features/change-review/`：一覧表示、確認、コメント、編集開始要求、削除要求を扱う。
- `src/features/box-editor/`：編集モード、枠の幾何操作、作成、削除、ページ別Undoを扱う。
- `src/features/viewer/`：拡大、パン、全体表示、表示範囲の通知を扱う。
- 新しいミニマップ表示：縮小Canvas、表示範囲、選択枠を描画し、パン要求をビューアへ渡す。
- `src/app/create-app.js`：変更IDによる選択と操作要求を各機能へ接続する。
- `src/app/bind-controls.js`：DOMイベントを各公開操作へ一度だけ委譲する。

ミニマップの座標変換はDOMから分離した純粋関数とし、単体テストできる形にする。

## 17. テスト方針

### 単体テスト

- 通常、選択枠編集、新規作成の状態遷移を検証する。
- 選択IDから編集対象の枠を正しく特定することを検証する。
- 新規作成、移動、八方向のリサイズ、削除、自動検出への復帰をUndoできることを検証する。
- Undo履歴がページごとに独立し、上限を守ることを検証する。
- コメント入力中のCtrl+Zが枠編集へ渡らないことを検証する。
- 図面座標、ミニマップ座標、表示範囲の相互変換を検証する。
- ミニマップの表示条件とページ境界への制限を検証する。

### 統合テスト

- 一覧の編集操作が対象ページ、選択ID、枠編集を同期することを検証する。
- 別項目の編集操作で対象だけが切り替わることを検証する。
- 新規枠が未確認の変更項目として一覧へ追加されることを検証する。
- 削除した項目が一覧と進捗から外れ、Undoで確認状態とコメントを含めて戻ることを検証する。
- 確認チェックがページ移動、パネル開閉、枠編集後も残ることを検証する。
- サイドバー開閉時に全体表示またはページ中心が維持されることを検証する。
- ズームとパンがミニマップの表示範囲へ反映されることを検証する。
- 古いページ移動、描画、索引の結果が新しい編集対象を上書きしないことを検証する。

### E2Eテスト

- 実PDFで一覧から編集を開始し、枠を移動して八方向にリサイズできることを検証する。
- 実PDFで新規枠を作成し、削除後にCtrl+Zで復元できることを検証する。
- 「対象外」が表示されず、確認チェックと進捗が連動することを検証する。
- サムネイル選択後にミニマップが現れ、クリックとドラッグで図面を移動できることを検証する。
- 全体表示へ戻したときにミニマップが消えることを検証する。
- 1280px幅と820px幅で、サイドバー、開閉ボタン、ミニマップが重ならないことを検証する。
- Chromium、Firefox、WebKitでポインター操作とキーボード操作を検証する。

既存の単体テスト、統合テスト、Playwright E2E、ビルドも全件実行する。

PNGおよびPDF出力、オフライン動作、差分モード、新旧切替モード、テキスト比較に回帰がないことを確認する。

実ブラウザでデスクトップ幅と狭幅の表示を確認し、静的なDOM検査だけを画面受け入れとはしない。

## 18. 受け入れ基準

1. 変更箇所サイドバーを境界上の`«`と`»`で開閉できる。
2. 各変更項目をチェックボックスで未確認または確認済みにできる。
3. 「対象外」の選択肢が表示されない。
4. 一覧項目の「編集」から、その枠だけを移動して八方向にリサイズできる。
5. 「＋ 新規変更箇所」から図面上のドラッグで枠を追加できる。
6. 一覧項目の「削除」で枠と項目を削除できる。
7. Ctrl+Zで現在ページの追加、移動、リサイズ、削除、自動検出への復帰を戻せる。
8. 削除をUndoすると、確認状態とコメントが同じ変更IDへ復元される。
9. サムネイル選択または手動ズームで拡大中に全体ミニマップを利用できる。
10. 全体ミニマップのクリックとドラッグが図面ビューのパンへ反映される。
11. サイドバー収納、ページ移動、モード変更で確定済みの枠編集とレビュー情報が失われない。
12. ミニマップ、選択表示、編集ハンドルがPNGおよびPDFへ出力されない。
13. PDFとレビュー情報を外部送信しない。
14. `npm test`、`npm run build`、Playwright E2Eが成功する。
