# 変更箇所リスト設計

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-09-07 |
| 対象 | Vite版 PDF差分レビューア |
| 関連資料 | `local/PDF-Diff-Reviewer_改善案.md` §3 |
| 実装範囲 | 図面比較の変更箇所一覧、レビュー状態、コメント、ナビゲーション、サムネイル |

## 1. 目的

図面比較で検出した変更枠を一覧にまとめ、レビュー担当者が各変更を順番に確認できるようにする。
一覧から変更箇所へ移動し、確認状態とコメントを記録できるようにすることで、差分の発見からレビュー完了までを同じ画面で扱う。

## 2. 適用範囲

| 対象 | 扱い |
|---|---|
| 図面比較の差分モード | 対象 |
| 図面比較の新旧切替モード | 対象 |
| テキスト比較モード | 対象外 |
| レビューセッションのファイル保存 | 対象外 |
| PNGおよびPDFへのコメント出力 | 対象外 |

レビュー情報はブラウザのメモリ上にだけ保持する。
外部API、テレメトリ、クラウドストレージは使用しない。

## 3. 採用する構成

レビュー情報を変更枠の座標データから分離する。
変更枠には内部IDを与え、レビュー情報はIDをキーとする別の状態として保持する。
この分離により、枠の複製、手編集、描画キャッシュの更新で確認状態やコメントが失われることを防ぐ。

不採用とした方式は次の二つである。

- 枠オブジェクトへレビュー情報を直接埋め込む方式は、既存の複製、Undo、自動検出への復帰で情報が欠落しやすい。
- ページ番号と座標からIDを毎回生成する方式は、DPI、位置合わせ、枠編集によってIDが変化する。

## 4. 画面構成

図面ビューアの右側へ幅320pxを基準とする「変更箇所」パネルを追加する。
パネルは開閉でき、閉じた場合は図面ビューアが空いた領域を使用する。
差分を初めて表示したときはパネルを開く。

画面幅が狭い場合は、パネルを図面ビューアの右側へ重ねるドロワーとして表示する。
ドロワーの外側を押す操作と閉じるボタンでパネルを閉じられるようにする。

パネル上部には次を固定表示する。

```text
変更箇所 17件
完了 6 / 17    未確認 11件

[前の変更] [次の変更]
```

ページごとに折りたためる見出しを置き、その配下へ変更項目をページ内の上から下、同じ高さでは左から右の順で並べる。
変更番号は全ページを通した表示順から採番し、内部IDには使用しない。

各項目には次を表示する。

- 変更番号
- ページ番号
- 種類（追加、削除、変更）
- 状態（未確認、確認済み、対象外）
- 変更箇所のサムネイル
- コメント入力欄

確認済みと対象外を完了として数える。
コメントの有無は完了条件に含めない。

## 5. 変更項目とレビュー情報

変更項目は現在の作業フレーム上の枠と、DPIに依存しない照合情報を持つ。

```js
{
  id: "change-<連番>",
  pageIndex: 0,
  pageKey: "old:0|new:0",
  rect: { x, y, w, h },
  normalizedRect: { x, y, w, h },
  kind: "added" | "removed" | "changed",
  source: "auto" | "manual"
}
```

`normalizedRect` は作業フレームの幅と高さを1とする座標で保持する。
`pageKey` は画面上のページ番号ではなく、ページ整列後のスロットに入っている旧版と新版の元ページ番号から作る。

レビュー情報は変更項目と別のMapへ保持する。

```js
{
  changeId: {
    status: "pending" | "confirmed" | "excluded",
    comment: ""
  }
}
```

状態は `pending` を初期値とする。
コメント入力は入力のたびにメモリ上の状態へ反映し、ページ移動やパネルの開閉では失わない。

## 6. 変更の種類

差分計算が使用するブロックフラグをビット値に拡張する。

- `1`：削除画素を含む
- `2`：追加画素を含む
- `3`：削除画素と追加画素を含む

連結成分から枠を作るときに構成ブロックのビット値を集約し、削除だけなら `removed`、追加だけなら `added`、両方なら `changed` とする。
手で追加した枠には `changed` を設定する。

この変更は枠の形状計算を変えない。
既存の赤、青、グレーの差分画像と削除、追加の画素数も変えない。

## 7. 全ページ索引

現行実装は表示したページの変更枠だけを計算する。
全変更件数と全ページを対象とする前後移動を実現するため、差分表示後に全ページの変更枠を索引化する。

処理順は次のとおりとする。

1. 現在ページを対話描画レーンで表示する。
2. 現在ページの変更項目を一覧へ反映する。
3. 残りのページを専用のバックグラウンドレーンで1ページずつ解析する。
4. 解析を終えたページから一覧、ページ別件数、全体件数を更新する。
5. 全ページの処理後に件数を確定する。

索引中は `変更箇所を分析中 4 / 12ページ` と表示する。
対話描画、索引、出力には別々のWorkerレーンを割り当てるため、索引処理がページ移動やPDF出力を占有しない。

文書世代と索引世代をチケットとして保持する。
PDFの差し替え、比較条件の変更、ページ整列によって世代が変わった場合、古い索引処理を停止し、その結果を状態へ反映しない。

あるページの解析が失敗しても残りのページは続行する。
失敗したページ見出しにはエラーと再試行操作を表示し、全件数が未確定であることを示す。

## 8. レビュー状態の自動引継ぎ

比較条件の変更前に、現在有効な変更項目とレビュー情報を移行用スナップショットへ退避する。
再検出した変更項目ごとに、同じ `pageKey` と `kind` を持つ旧項目を候補として照合する。

候補の類似度は次で計算する。

```text
score = 0.65 × IoU
      + 0.20 × centerSimilarity
      + 0.15 × sizeSimilarity
```

`centerSimilarity` は正規化座標上の中心距離が0なら1、0.25以上なら0となる線形値とする。
`sizeSimilarity` は小さい方の面積を大きい方の面積で割った値とする。

次の条件をすべて満たす一対一対応だけを引き継ぐ。

- IoUが0.50以上である。
- `score` が0.72以上である。
- 新旧の項目が互いを最良候補として選ぶ。
- 第2候補がある場合、最良候補との `score` の差が0.10以上ある。

対応が確定した新項目は旧項目のID、状態、コメントを継承する。
種類が変化した項目、分割または結合された項目、条件を満たさない項目は新しいIDを持つ未確認項目とする。
誤った変更へ「確認済み」が移ることを避けるため、曖昧な対応を近傍順だけで引き継がない。

移行後は `レビュー12件を継承し、2件を未確認へ戻しました` の形式で結果を通知する。
新しく検出された項目と曖昧な項目は、どちらも未確認へ戻した件数に含める。

PDFを差し替えた場合は移行を行わず、レビュー状態をすべて初期化する。

## 9. 枠編集との連携

枠の移動とリサイズではIDを維持し、レビュー状態とコメントを残す。
枠を手で追加した場合は新しいIDを発行し、種類を `changed`、状態を `pending` とする。

枠を削除した場合、一覧からは直ちに除外するがレビュー情報は内部に残す。
Undoで同じIDの枠が復元された場合、削除前の状態とコメントも復元できる。
Undo履歴から到達不能になったレビュー情報は、次の比較条件変更またはPDF差し替えで破棄する。

「自動検出に戻す」では自動枠が持つ元のIDを復元する。
手動追加枠は一覧から外れるが、Undoと同じ理由でレビュー情報を直ちに削除しない。

一覧で選択した項目のIDと、枠編集で選択した枠のIDを同期する。
ただし、一覧から項目を選んだだけでは枠編集モードへ切り替えない。

## 10. ナビゲーション

一覧項目を選ぶと、対象ページを表示してから対象枠を図面ビューアの中央へ移動する。
対象枠の周囲に25%の余白を確保できる倍率を計算し、自動倍率は400%を上限とする。
利用者が選択後に手動でズームする操作は制限しない。

「前の変更」と「次の変更」はページ番号とページ内座標で並べた全項目を巡回する。
末尾で「次の変更」を押した場合は先頭へ、先頭で「前の変更」を押した場合は末尾へ移動する。

選択中の一覧項目と対応する変更枠には、通常のオレンジ枠に白い外周線を追加する。
この選択表示は画面用オーバーレイだけに描き、PNGおよびPDFには出力しない。

## 11. サムネイル

サムネイルは一覧へ表示するための低解像度画像であり、レビュー状態には含めない。
高DPIの全ページ画像を保持するとメモリ使用量が増えるため、表示が必要なページグループだけ遅延生成する。

生成時は対象ページを72 DPI相当で差分描画し、同じページに属する変更枠を正規化座標で切り出す。
枠の周囲へ15%の余白を加え、120×80 CSS pxの領域へ収める。
同じページのサムネイルは1回の低解像度描画からまとめて作り、ページ単位でキャッシュする。

比較条件またはページ整列が変わった場合はサムネイルキャッシュを破棄する。
生成に失敗した項目にはプレースホルダーを表示し、レビュー操作は継続できるようにする。

## 12. 状態とモジュール境界

`state.review` に次を保持する。

- ページ別の変更項目
- ID別のレビュー情報
- 選択中の変更ID
- パネルの開閉状態
- 索引の世代、進捗、ページ別エラー
- 再検出前の移行用スナップショット
- ページ別のサムネイルキャッシュ

純粋な計算は `src/core/change-review/` に置く。
ここには種類の集約、正規化、表示順、件数集計、再検出時の照合を含める。

画面状態と操作は `src/features/change-review/` に置く。
レビューコントローラが全ページ索引、選択、状態変更、コメント、枠編集との同期を担当し、レビュー表示がDOM更新とサムネイル表示を担当する。

既存モジュールの責務は次のように保つ。

- 差分計算は画素比較と種類付き変更枠を返す。
- 図面描画は現在ページのCanvasと変更枠を反映する。
- 枠編集は枠の幾何操作とUndoを担当する。
- ビューポートは矩形へのフォーカス計算を担当する。
- アプリ生成処理は各コントローラとWorkerレーンを接続する。

## 13. エラー処理と競合制御

- 古い文書世代、描画世代、索引世代の結果はコミットしない。
- バックグラウンド索引を停止しても、すでに確定したレビュー入力は移行用スナップショットへ残す。
- ページ移動中に別の項目が選ばれた場合は、最後に選ばれた項目だけを表示してフォーカスする。
- コメント入力中の再描画では入力欄のフォーカスとカーソル位置を維持する。
- サムネイルの失敗は一覧本体の失敗として扱わない。
- PDFの解析に失敗した場合は既存のエラー表示経路へ渡し、処理中表示を解除する。

## 14. テスト方針

### 単体テスト

- 削除だけ、追加だけ、両方を含む連結成分へ正しい種類を付ける。
- 正規化座標と表示順をページ寸法およびDPIに依存せず計算する。
- 状態別、ページ別、種類別の件数を集計する。
- 高確度の一対一対応だけがレビュー情報を継承する。
- 種類変更、低IoU、同点候補、分割、結合では継承しない。
- 矩形フォーカスが余白と倍率上限を守る。

### 統合テスト

- 現在ページの表示後に残りのページを順次索引化する。
- 世代が変わった古い索引結果を反映しない。
- ページ単位の失敗後も残りの索引を続ける。
- 一覧選択、前後移動、状態変更、コメント入力を状態へ反映する。
- 枠の移動、リサイズ、削除、Undo、自動検出への復帰とレビュー情報を同期する。
- 比較条件変更後に高確度項目だけを引き継ぐ。
- PDF差し替えではレビュー情報を初期化する。
- 低解像度ページ描画を再利用してサムネイルを生成する。

### E2Eテスト

- 複数ページの実PDFから全変更件数とページ別件数を表示する。
- 一覧項目の選択でページ、倍率、位置、選択枠が連動する。
- 前後移動がページ境界を越えて巡回する。
- 確認済み、対象外、コメントがページ移動後も残る。
- 設定変更後に継承件数を通知し、曖昧な項目を未確認へ戻す。
- 枠編集とUndoで一覧およびレビュー情報が同期する。
- パネルの開閉と狭幅ドロワーを確認する。
- サムネイルの生成中と失敗時にもレビュー操作を続けられる。

既存の単体テスト、統合テスト、Playwright E2E、ビルドも全件実行する。
デスクトップ幅と狭幅で実ブラウザ表示を確認し、静的なDOM検査だけを画面受け入れとはしない。

## 15. 受け入れ基準

1. 図面比較で変更箇所パネルを開閉できる。
2. 全ページの変更項目をページ別に表示し、全件数、未確認件数、完了件数を確認できる。
3. 各項目へ追加、削除、変更の種類とサムネイルを表示できる。
4. 一覧選択および前後操作で対象ページと対象枠へ移動できる。
5. 各項目を未確認、確認済み、対象外へ変更し、コメントを保持できる。
6. 確認済みと対象外を完了として集計できる。
7. 枠の移動、リサイズ、削除、Undo、自動検出への復帰と一覧が同期する。
8. 再検出時は高確度で対応する項目だけが状態とコメントを継承する。
9. 索引、対話描画、PDF出力が互いのWorker処理を不当に打ち切らない。
10. テキスト比較、差分画像、差分および新旧切替の表示モード、PNG/PDF出力に回帰がない。
11. PDFとレビュー情報を外部送信しない。
12. `npm test`、`npm run build`、Playwright E2Eが成功する。
