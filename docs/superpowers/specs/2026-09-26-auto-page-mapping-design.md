# 自動ページ対応付け設計

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-09-26 |
| 対象 | Vite版 PDF差分レビューア |
| 出典 | `local/PDF-Diff-Reviewer_改善案.md` §6 自動ページ対応付け |
| 実装範囲 | ページ類似度の計算、順序を保つ自動整列、読み込み時の提案、要約表示、Undo |

## 1. 目的

改訂でページが追加・削除された図面を比較するとき、現在は利用者が「この旧ページは削除されたページ」「この新ページは追加されたページ」を1ページずつ操作して整列している。

ページの類似度から新旧ページの対応を自動で求め、既存の整列モデル（空白スロットの挿入）へ反映する。

## 2. 適用範囲

| 対象 | 扱い |
|---|---|
| 途中・先頭・末尾へのページ追加 | 対象 |
| 途中・先頭・末尾のページ削除 | 対象 |
| 90°単位で回転したページの対応付け | 対象 |
| ページ順の入れ替え | 対象外（削除＋追加として表示される） |
| 適用前のプレビュー・一覧上での対応修正 | 対象外（適用後に既存の手動整列と Undo で直す） |
| テキスト内容による類似度 | 対象外 |
| バッチ比較 | 対象外（本機能の後続） |

処理はすべてブラウザ内で完結させ、PDFや解析結果を外部へ送信しない。

## 3. 前提となる既存モデル

- ページ対応は `state.documents.oldSequence` / `newSequence` で表す。要素は元PDFのページ番号（0始まり）、空白スロットは `null`。
- 手動整列は現在スロットに `null` を挿入し、`alignmentOps` に `{ side, slot }` を積む。「↩ 取り消す」は末尾の操作を1件戻す。
- 整列変更後の差分・索引の再計算は `visualController.refreshAfterAlign` が行う。

このモデルは順序を保つ挿入・削除だけを表せる。本機能も同じ制約の中で対応を求める。

## 4. 構成

| 層 | ファイル | 役割 |
|---|---|---|
| core | `src/core/page-mapping/page-mapping.js`（新規） | マスク生成・類似度・DP・要約文生成（純粋関数） |
| workers | `src/workers/diff-worker.js` | ジョブ `pageSignature`（1ページ分のマスク生成）と `pageMap`（対応付け）を追加 |
| features | `src/features/documents/page-mapping-controller.js`（新規） | 全ページの低解像度描画、Worker 呼び出し、進捗・世代管理 |
| app | `src/app/create-app.js`・`bind-controls.js`・`dom.js` | ボタン・提案・要約・Undo の配線 |
| markup | `index.html` | 「ページ整列」欄へのボタンと表示欄の追加 |

レイヤ境界（`dependency-boundaries.test.js`）に従い、core は DOM を参照せず、feature は app と他の feature を import しない。

## 5. 処理の流れ

1. 旧新PDFの読み込みが完了し、ページ数が異なる場合は提案を表示する。
2. 利用者が「自動でページ整列」を押す。
3. 旧・新の各ページを長辺 1024px で順に描画し、画素を Worker の `pageSignature` へ転送して 64×64 マスクを受け取る。描画した Canvas は受け取り後すぐ破棄する。
4. 全マスクを Worker の `pageMap` へ渡し、新しい `oldSequence` / `newSequence` と各対応の類似度を受け取る。
5. 結果を適用する。差分表示済みなら `refreshAfterAlign` 経由で差分と索引を再計算する。
6. 要約を表示する。

ボタンは旧新PDFが両方読み込まれていれば有効とし、「差分を表示」の前でも実行できる。

## 6. 計算

### 6.1 ページマスク（`pageSignature`）

- 画素を比較設定と同じしきい値（`comparison.threshold`）でインク／背景に2値化する。
- 既存の `downsampleMaskMax` で 64×64 の正方形グリッドへ最大値プーリングで縮小する。
- 縦横比は正方形へ正規化する。90°回転はマスクの回転だけで比較できる。

### 6.2 類似度

`sim(i, j)` = 旧ページ i のマスクと、新ページ j のマスクを 0°/90°/180°/270° 回転したものとの `inkIoU` の最大値。

両方白紙なら 1、片方だけ白紙なら 0（`inkIoU` の既存挙動）。

### 6.3 対応付け（`pageMap`）

順序を保つ系列アラインメント（Needleman–Wunsch）で合計点を最大化する。

```text
S[i][j] = max( S[i-1][j-1] + (sim(i,j) − τ),   // 旧 i と新 j を対応
               S[i-1][j],                      // 旧 i を削除
               S[i][j-1] )                     // 新 j を追加
```

- 空白の挿入には点を与えない。`sim < τ` のページは対応させず、削除＋追加とする。
- 同点のときは対応を優先する。これにより、ページ数が同じで各ページが τ 以上なら結果は現状と同じ順の対応になる。
- 逆向きにたどった結果を `oldSequence` / `newSequence` に変換する。削除と追加が隣接する場合は削除を先に並べる。

### 6.4 定数

| 定数 | 初期値 | 意味 |
|---|---|---|
| `SIGNATURE_LONG_EDGE` | 1024 | 解析用描画の長辺 px（細線が2値化で消えない解像度） |
| `SIGNATURE_GRID` | 64 | マスクのグリッド数 |
| `MATCH_MIN`（τ） | 0.6 | 対応とみなす最低類似度 |
| `LOW_SIMILARITY` | 0.8 | 要約で「類似度が低い対応」として示す上限 |

τ は実図面で校正できないため、合成データで決める（§9）。定数は1箇所にまとめ、`ponytail:` コメントで「合成データで決めた値であり、実図面で誤判定が出たらここを調整する」と明記する。

## 7. 状態・Undo・UI

### 7.1 Undo

- 自動整列は1件の操作として `alignmentOps` に積む: `{ kind: "auto", oldSequence: 適用前の複製, newSequence: 適用前の複製 }`。
- 「↩ 取り消す」で `kind: "auto"` を戻すと、適用前の並びへ一括で復元する。既存の `{ side, slot }` 操作の扱いは変えない。
- 自動整列は、手動整列の有無にかかわらず元のページ順から計算し直して置き換える。置き換え前の状態は Undo で戻せる。
- 結果が現在の並びと同じなら操作を積まず、「変更はありませんでした」と表示する。

### 7.2 変更枠との関係

手動整列と同様に、適用前に `confirmDiscardBoxEdits()` で手編集した変更枠の破棄を確認する。拒否されたら適用しない。

### 7.3 UI

「ページ整列」欄の先頭に次を追加する。

- `#alignAuto`: 「自動でページ整列」ボタン（全幅）
- `#pageMapNotice`: 状態表示欄

`#pageMapNotice` の表示内容:

| 状態 | 表示例 |
|---|---|
| 提案（ページ数が異なる） | ページ数が異なります（旧 12／新 13）。自動でページ整列できます |
| 実行中 | ページを解析中… 25/50 |
| 完了 | 旧 P3 を削除、新 P4 を追加と判定。類似度が低い対応：スロット 5（62%） |
| 変更なし | 変更はありませんでした |
| 失敗 | 新版 P7 の解析に失敗したため自動整列を中止しました |

提案表示中は `#alignAuto` を強調表示する。提案は自動整列の実行、またはPDFの再読み込みで消える。

実行中は `#alignAuto` と手動整列ボタンを無効化する。中断ボタンは設けない。

ヘッダーの更新日と `documentation.test.js` の日付を実装日に揃える。

## 8. エラー処理

- いずれかのページの描画または Worker 処理に失敗したら、自動整列全体を中止し、並びを変更せずに失敗を表示する。
- 実行中にPDFが再読み込みされたら（`documents.generation` の変化）、結果を破棄して何も表示しない。
- ページ数が同じで全対応が τ 未満の場合は、全ページ削除＋全ページ追加の結果をそのまま適用し、要約に表示する（Undo 1回で戻せる）。

## 9. テスト

### 9.1 unit（`tests/unit/page-mapping.test.js`）

合成マスクで次を検証する。

- 中間への挿入、中間の削除、先頭・末尾の増減
- ページ数が同じで各ページが類似なら現状の順の対応
- 90°回転したページの対応
- 白紙ページ
- 要約文の生成

### 9.2 τ の校正

jsPDF で共通の図枠・表題欄を持ち内容だけが異なるA3シート群（`sheets-old.pdf` / `sheets-new.pdf`）を合成し、e2e のブラウザ内で pdf.js 描画から次の分布を測る。

- 別シートどうしの類似度
- 同一シートに部分改訂を加えたものとの類似度

両者の間に τ を置き、この分離をテストで固定する。

### 9.3 integration（`tests/integration/create-app.test.js`）

- ページ数が異なるときに提案を表示する
- 適用で並びが更新される
- Undo 1回で適用前に戻る
- 結果が現状と同じなら操作を積まない
- 失敗時に並びを変更しない

### 9.4 e2e

`tests/fixtures/generate-fixtures.mjs` で旧5シート・新6シート（3枚目に新規シートを挿入し、旧3枚目は部分改訂）のフィクスチャを生成する。読み込み → 提案表示 → 実行 → スロット数と要約の確認を3ブラウザで行う。サイドバーの見た目が変わるため、`baseline.spec.js` のスナップショットを更新する。
